# 🎯 나만의 파이썬 퀴즈 게임 (Python Console)

Python 기초 문법과 객체 지향 프로그래밍(OOP), JSON 파일 입출력을 완벽히 이해하기 위해 제작된 터미널 기반 대화형 퀴즈 게임입니다. 

단순히 코드를 동작하게 만드는 것을 넘어, **"왜 이 기술(클래스, JSON, Git 브랜치)을 선택했는지"**에 대한 기술적 근거와 한계점까지 치열하게 고민하여 설계했습니다.

---

## 🚀 1. 프로젝트 개요 및 실행 방법
* **개발 환경:** Python 3.10 이상 (외부 라이브러리 없음)
* **실행 방법:**
  1. 저장소를 클론(Clone) 받거나 폴더로 이동합니다.
  2. 터미널(Git Bash 또는 PowerShell)을 열고 아래 명령어를 입력합니다.
```bash
python main.py
# 윈도우 환경에 따라 py main.py 또는 python3 main.py 를 사용하세요.
```

---

## ✅ 2. 주요 기능 및 튼튼한 방어 코드 (예외 처리)

사용자가 실수로 이상한 값을 입력해도 **절대 프로그램이 튕기지 않도록(Crash)** 방어 코드를 단단하게 구축했습니다.

1. **퀴즈 풀기 및 채점:** 
   - 1~4번 중 하나를 입력해 정답을 맞힙니다. 
   - 🛡️ **방어 코드:** 숫자 대신 문자(`abc`)를 입력하거나, 범위를 벗어난 숫자(`9`), 혹은 아무것도 입력하지 않고 엔터만 쳤을 때 프로그램이 종료되지 않고 안내 메시지와 함께 재입력을 요구합니다. (`try-except` 활용)
2. **퀴즈 추가 및 영속성:**
   - 새로운 퀴즈를 직접 추가할 수 있습니다.
   - 🛡️ **영속성 보장:** 퀴즈를 추가하거나 최고 점수를 갱신하면 즉시 `state.json`에 기록됩니다. 프로그램을 껐다 켜도 데이터가 100% 유지됩니다.
3. **안전 종료 (Ctrl+C / EOF):**
   - 사용자가 강제로 프로그램을 끄려 할 때도 에러를 뱉지 않고 "게임을 안전하게 종료합니다."라는 메시지와 함께 우아하게(Graceful) 종료되도록 예외 처리를 덧붙였습니다.

## 💡 3. 왜 클래스로 나누었을까? (객체지향 설계 근거)

모든 코드를 함수로만 짤 수도 있었지만, 관련된 데이터와 동작을 하나의 캡슐로 묶어 **유지보수와 확장을 쉽게 만들기 위해** 클래스를 도입했습니다. 각각의 역할을 완벽히 분리했습니다.

* **`Quiz` 클래스 (개별 퀴즈 카드):** 
  * "문제 내용, 4개의 선택지, 정답 번호"라는 데이터를 하나로 묶어 담아두는 '틀'입니다.
* **`QuizGame` 클래스 (게임 진행자):** 
  * 퀴즈 카드들을 모아서 섞고, 점수를 계산하고, 파일을 읽고 쓰는 **핵심 비즈니스 로직(운영)**을 담당합니다.
* **`main.py` (안내데스크):** 
  * 사용자의 키보드 입력을 받고 화면에 메뉴를 띄워주는 **UI(User Interface) 역할**만 수행합니다.

> **설계의 장점:** 만약 화면 출력을 터미널에서 웹(Web)이나 앱(App)으로 바꾸고 싶다면? 핵심 로직이 들어있는 `QuizGame`이나 `Quiz`는 단 한 줄도 건드릴 필요 없이 `main.py`만 교체하면 됩니다! 이것이 책임을 분리한 가장 큰 이유입니다.

## 💡 4. 왜 JSON을 사용했을까? (데이터 저장 원리)

데이터 저장을 위해 일반 텍스트(.txt)나 CSV가 아닌 **JSON**을 선택했습니다.

* **선택 이유:** JSON은 파이썬의 `Dictionary(딕셔너리)` 자료형과 구조가 거의 완벽히 일치합니다. 따라서 파이썬 코드에서 불러오거나 내보낼 때 변환 과정이 매우 직관적이고 코드가 깔끔해집니다. 또한 계층적(중첩된) 데이터를 표현하기 가장 좋습니다.
* **🛡️ 파일 손상 대비 (자동 복구 로직):**
  * 사용자가 실수로 `state.json`을 삭제했거나, 파일 내용이 깨져서 파싱(Parsing)에 실패하는 최악의 상황을 가정했습니다.
  * 프로그램 시작 시 `try-except json.JSONDecodeError` 및 `FileNotFoundError`를 통해 에러를 감지하면 프로그램이 죽는 대신, **미리 준비된 기본 5문제로 자동 복구(초기화)**하여 `state.json`을 새로 만들어냅니다. 절대 데이터를 잃고 멈추지 않습니다.

## 💡 5. Git 브랜치 전략과 협업 마인드

코드를 통째로 한 번에 올리는 대신, 철저하게 **기능 단위 커밋**과 **브랜치(Branch)** 전략을 사용했습니다.

* **기능 단위 커밋:** "메뉴 추가", "점수 계산 로직 추가", "오류 처리 보완" 등 의미 있는 단위로 쪼개어 커밋했습니다. 누군가 히스토리를 봤을 때 "아, 이때 이런 이유로 이 코드를 추가했구나"를 한눈에 알 수 있습니다.
* **브랜치를 나눈 이유 (평행 우주):** 
  * `main` 브랜치는 언제나 완벽하게 동작하는 안정적인 배포 버전이어야 합니다. 
  * 새로운 기능(예: 퀴즈 추가 기능)을 개발할 때는 `feature` 브랜치를 새로 파서(마치 평행우주를 만들듯) 그곳에서 온갖 테스트와 실패를 겪으며 코딩합니다.
  * 완벽하게 완성되었을 때만 `main`으로 합침(Merge)으로써, 프로젝트의 안정성을 100% 보장했습니다.

## 🤔 6. 심층 면접 (Q&A) 방어

설계 과정에서 마주했던 한계점과 그에 대한 대응책을 정리했습니다.

**Q. 만약 퀴즈 데이터가 1000개, 10000개로 늘어난다면 현재 JSON 방식에 한계가 있을까요?**
> **A.** 네, 치명적인 한계가 발생합니다. 현재 방식은 프로그램 시작 시 `state.json` 전체를 한 번에 메모리(RAM)로 불러오고, 끝날 때 전체를 다시 덮어씁니다. 데이터가 수만 개가 되면 시작 속도가 기하급수적으로 느려지고 메모리 터짐(OOM) 현상이 발생할 수 있습니다. 
> 데이터가 방대해진다면 필요한 퀴즈만 그때그때 꺼내올 수 있는 **SQLite 같은 진짜 데이터베이스(DB) 시스템으로 반드시 전환**해야 합니다.

**Q. "선택지를 4개에서 5개로 늘려라" 혹은 "점수 계산 방식을 바꿔라"라는 요구사항이 생기면 어디부터 수정해야 할까요?**
> **A.** 앞서 클래스로 역할을 철저히 분리했기 때문에 순차적으로 수정하면 파급력을 최소화할 수 있습니다.
> 1. **데이터 구조:** 가장 먼저 `state.json`에 저장되는 스키마와 이를 담는 `Quiz` 클래스를 수정합니다.
> 2. **비즈니스 로직:** 다음으로 변경된 구조에 맞게 점수를 계산하는 `QuizGame` 클래스 내부의 메서드를 수정합니다.
> 3. **UI 출력 부분:** 마지막으로 화면에 5개의 선택지를 띄워주도록 `main.py`의 출력(print) 부분만 수정하면 완벽하게 반영됩니다.
